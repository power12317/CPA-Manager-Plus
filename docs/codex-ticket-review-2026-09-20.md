## 已确认的问题与整改

| 问题 | 原行为 | 修正 |
| --- | --- | --- |
| 保存确认误当配置 | PUT 经 persist 返回 `{"status":"ok"}`，前端归一化为关闭、空模型、空代理及默认参数 | API 更新返回 void；配置界面不再独立调用此保存接口 |
| 两条保存路径互相覆盖 | 门票卡片自己的保存不更新整页 YAML 基线，源码或可视化草稿可能覆盖新值 | 四个门票字段纳入 useVisualConfig 脏字段、统一差异预览与保存 |
| 草稿被异步加载覆盖 | 切换语言、晚到请求会重写本地字段 | 卡片由父级草稿控制；GET 只探测能力，不写入表单 |
| 旧服务及实例隔离 | 404 只显示一般错误；请求无卸载保护 | 404/405 明确标为不支持；按基址和管理密钥捕获范围，切换及卸载取消请求并忽略晚到结果 |
| 静默轮询抢占 | 后台请求更新 requestID，前台请求无法清除 loading，后台自己也不清除 | 后台请求不抢占进行中的加载；同一轮去重，手动刷新可取代后台请求 |
| 后台结果覆盖更新 | 请求期间凭证可能被操作修改 | 检查凭证数据版本，丢弃修改前的后台快照；保留现有实例、卸载和最新请求检查 |
| 倒计时过期不及时 | remaining_seconds 只在网络刷新时变化 | 接收公开状态时记录本地观测时间，每秒重算；同时受 expires_at 限制，过期不再显示 ready |

## 数据与保存契约

- 凭证列表、卡片及详情仅使用 `GET /v0/management/auth-files` 的
  `codex_turn_tickets`，按模型展示 ready、剩余有效时间、blocked 或缺票。
- 门票数组使用公开字段白名单归一化，意外附带的 token/value 等字段不会进入展示模型；
  不展示门票原文。旧服务缺少该字段时不增加空区块。
- `GET /v0/management/codex-turn-state-ticket` 用于原生能力检测；
  非策略响应不能按默认配置解释。
- `PUT/PATCH /v0/management/codex-turn-state-ticket` 返回保存确认，不是完整策略。
- 界面统一读写现有配置 YAML 流程，节点为
  `codex.turn-state-ticket`；可编辑 `enabled`、`fail-closed`、
  `harvest-proxy-url`、`models`。未修改的 TTL、刷新阈值、超时、
  目标长度及其他配置保持原值，源码草稿和注释按原页面流程保留。
- 代理输入使用密码框；清空并保存会移除代理值。管理 YAML 本身属于有权限用户可读的原始配置，
  隐藏输入不是后端脱敏。页面不使用脱敏 GET 值回写原始代理。
- 模型去重且保持大小写，空列表沿用后端默认
  `gpt-6-astra`、`gpt-5.6-sol`。

后端规则说明：配置范围内有效的账号＋模型 292 门票强制替换请求中的状态，
与 turn_id 无关。收到 312 后门票失效并重新探测。
`fail-closed: false` 时无票仍继续发送，有效票仍强制替换。
前端不会自行推断过期后一定 blocked；blocked 以服务端返回为准，
过期到下一次状态刷新之间显示缺票。
